> 目的不是背命令，而是建立正确的心理模型——知道"哪一步在做什么、哪里可能出错"。

## 一、Git 和 GitHub 是两个东西

这是最容易混的一点。

| | Git | GitHub |
|---|---|---|
| 是什么 | **软件**，装在你电脑上 | **网站**，需要联网 |
| 干什么 | 记录文件的历史版本 | 替你保管代码、展示给他人看 |
| 在哪 | `mini-hot\.git` 文件夹 | `github.com/Panky-pan/mini-hot` |
| 没有它行不行 | 不行，版本控制靠它 | 行，可以只用本地 Git |

**打个比方**：Git 是你家的保险柜，GitHub 是银行的保险箱。你可以只用保险柜（纯本地开发），也可以把东西存到银行（推送到 GitHub）。

**关键结论**：就算 GitHub 挂了或连不上，你本地那份代码和全部历史依然完好。这也是「卡住降级」方案成立的原因——GitHub 注册受阻时，只用本地 Git 也能继续开发。

## 二、一次提交经历的四个阶段

```text
① 工作区  ──add──▶  ② 暂存区  ──commit──▶  ③ 本地仓库  ──push──▶  ④ GitHub
改文件              待提交清单            已存成历史            云端备份
```

| 阶段 | 含义 | 出问题的典型症状 |
|---|---|---|
| ① 工作区 | 你实际编辑的文件 | 改了文件但忘了保存 |
| ② 暂存区 | 挑出来"准备提交"的文件清单 | 忘了 `add`，`commit` 时没东西可提交 |
| ③ 本地仓库 | 已存成历史记录，**代码此时已安全** | 提交说明写错，可用 `--amend` 修 |
| ④ GitHub | 推送到云端 | 需要联网 + 身份验证，最常见的失败点 |

**最重要的一点**：`commit` 之后代码就已经安全存在本地仓库了。即使 `push` 失败，代码也不会丢。这一点能消除一大部分焦虑。

## 三、.gitignore 的防线与它的失效场景

`.gitignore` 的作用是告诉 Git「这些文件请假装看不见」。

### 情况一：新文件 —— 能拦住 ✅

```text
新建 .env（含密码） ──▶ 检查忽略规则 ──▶ 命中 ──▶ 被排除在外，不会上传
```

### 情况二：已被跟踪的文件 —— 拦不住 ❌

```text
.env 已提交过 ──▶ 忽略规则不再检查 ──▶ 照常提交推送 ──▶ 密码泄漏
```

**原因**：`.gitignore` 只对**还没被 Git 跟踪**的文件生效。一旦某文件被 `git add` 或 `git commit` 过，之后再写进 `.gitignore` 也不会把它移除。

**补救命令**：

```bash
git rm --cached 文件名     # 从 Git 跟踪列表摘掉，保留本地文件
```

**结论**：忽略规则必须**提前**写好——在文件第一次进入暂存区之前。这就是为什么项目第一天就要建 `.gitignore`，而不是等用到数据库时再补。

**万一密钥已经推送出去了**，顺序很重要：
1. 立刻去发密钥的平台**作废 / 轮换**那个密钥（最重要，Git 历史很难彻底清除）
2. 再从仓库移除文件
3. 加进 `.gitignore`
4. 重新提交

## 四、关于推送权限的认知纠正

**误区**：以为 `git push` 需要"工具拥有 GitHub 权限"。

**真相**：推送用的是**你自己的凭据**，和用什么工具无关。

- 登录授权只在**第一次**需要，浏览器弹出授权页 → 点同意 → 凭据被 Git Credential Manager 存进系统
- 之后 `git push` 静默完成，不再弹窗
- 工具（无论是 WorkBuddy、ChatGPT 还是终端）只是**执行命令的手**，它没有也不需要 GitHub 账号

**常见报错辨析**：

| 报错 | 含义 | 是不是权限问题 |
|---|---|---|
| `could not read Username ... terminal prompts disabled` | 要用户名但无法弹出输入框 | ❌ 不是，是登录流程走不下去 |
| `CONNECT tunnel failed, response 502` | 网络被拦截，连不上 | ❌ 不是，是网络问题 |
| `403 Forbidden` / `Permission denied` | 确实无权访问 | ✅ 这才是权限问题 |

**一句话记住**：GitHub 认的是**你的人**，不是你的工具。

## 五、这几个词在项目里对应什么

| 概念 | 你的实际情况 |
|---|---|
| Git（软件） | 装在电脑上，版本 2.55.0 |
| GitHub（网站） | `github.com/Panky-pan/mini-hot`，公开仓库 |
| 仓库 | 本地 `.git` 文件夹 + 云端同名仓库 |
| 提交 | 每次 `commit` 产生一条记录，有唯一编号（如 `cb94f4d`） |
| 分支 | `main` —— 唯一的，也是默认的 |
| `.gitignore` | 已生效，`.env` 三种写法全部命中 |
| 远程 / origin | `remote origin` 指向你的 GitHub 仓库 |

**关于分支**：一个人开发时通常只有一个分支。将来要试新功能又不想弄坏现有代码时，才会开新分支。

## 六、日常操作只有三条命令

```bash
git add .                    # 把改动放进暂存区
git commit -m "说明你改了什么"  # 存成本地历史
git push                     # 送到 GitHub
```

提交前建议先 `git status` 看一眼，确认没有敏感文件混进去。
